The pipeline

Four commands, run in order

Staged on purpose: each step writes a file you can inspect before the next one runs. Nothing reaches GitHub until you say so.

01
doctor

Preflight: verifies gh auth, the claude CLI, and a live Odoo login.

02
fetch

Builds the context bundle — diff, Odoo task, tests, full files, references, house rules.

03
review

Runs Claude + a skeptical critic pass → editable findings with confidence & verdict.

04
push

Posts one draft review (summary + inline comments) for you to submit.

By design

Human → AI → human

The AI is wedged between two humans — it never gets the first word or the last.

Human first

A person reviews & comments

review refuses to run until a real human (not a bot, not the author) has weighed in.

→
AI on top

Reinforces or challenges

Reads the existing comments, backs the right ones, pushes back on the wrong ones, adds its own.

→
Human last

You have the final say

Edit review.json, then submit the draft — nothing posts without your click.

Calibrated for PS Tech

Reviews customizations, not core

The odoo-review guidelines (all sibling skills are fetched and fed in) target contributions to Odoo core. By default the review is recalibrated for customer implementations built on top of Odoo — in priority order.

1

Maintainability

Readable, minimal surface, upgrade-safe — inherit & extend (_inherit / super() / xpath), never patch core.

2

Correctness

Does what the linked task / SOW asks, edge cases included.

3

Odoo-like, minimal code

Standard config · Studio · server actions · existing modules — before any bespoke Python.

4

Performance

At the customer's real data volume — no N+1, no queries in loops.

5

Security

Access rights, record rules, careful sudo() — genuine holes always flagged.

Challenges the business need Proposes a better data model Footprint & ROI verdict — best code is no code

Capabilities

What's in the box

Sandbox & privacy

The AI is locked out

  • No MCP, every built-in tool disabled, empty working dir
  • Only the script talks to GitHub & Odoo
  • Sandbox audit via permission_denials
  • Runs on your own claude login — no extra billing
Context it gathers

More than the diff

  • Odoo task description + chatter from the [task_id]
  • The touched modules' tests as API reference
  • Full changed files + target-branch callers
  • odoo-review house rules + all sibling guidelines at the base branch
Review quality

Signal over noise

  • Critic pass refutes each finding → verdict
  • Confidence threshold suppresses weak findings
  • Dedups against comments already on the line
  • Every finding anchored to a real diff line
Strategies

Scale to the PR

  • whole — one pass over the PR
  • per-task — group by [task_id] + synthesis
  • per-commit — one agent per commit
  • --incremental — only new commits since last run
Delivery

Draft, not drive-by

  • One review: summary + inline comments
  • ```suggestion``` blocks for one-click fixes
  • --dry-run, confirm prompt, draft default
  • One-pending-review guard, hidden idempotency marker
Security hardening

Hostile PR text, handled

  • Strips zero-width / bidi / control characters
  • Wraps PR text in <<<UNTRUSTED>>> fences
  • System prompt: data, never instructions
  • Covers the diff & code, not just metadata

Output

What a finding looks like
